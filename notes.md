токенов рядом со светлыми в index.css, автоматическое переключение по системной теме
устройства (`prefers-color-scheme`) или ручной переключатель в Аккаунте — не обсуждали).
Вернуться к этому отдельным разговором, когда дойдём до темы.

## Сделать это настоящим приложением для телефона (2026-07-22)

Пользователь хочет со временем оценивать работу приложения прямо с телефона, не только на компьютере.
Варианты (не выбраны, решим когда дойдём):
- **Проще всего прямо сейчас**: открыть на телефоне уже опубликованную ссылку на артефакт — она работает в любом браузере.
- **Во время разработки**: запускать `npm run dev -- --host`, чтобы телефон (в той же Wi-Fi сети) видел сайт по локальному адресу компьютера.
- **PWA (Progressive Web App)**: относительно небольшая доработка — добавить файл манифеста и иконку, чтобы сайт можно было "установить" на домашний экран телефона и он выглядел как настоящее приложение. Не требует переписывания на другой язык.
- **Настоящее нативное приложение** (Swift/iOS или React Native): самый большой по объёму работ вариант, переписывание либо оболочки, либо всего приложения.

## Дизайн-вдохновение: тёмный "аудио-консоль" интерфейс (2026-07-22)

Пользователь прислал скриншот UI (не из нашего проекта - похоже на экран записи звука) и попросил
запомнить этот дизайн как ориентир на будущее. Описание для восстановления стиля:
- Почти чёрный фон, минимум цвета (в основном градации серого + один красный акцент).
- Мелкие подписи КАПСОМ моноширинным шрифтом в углах ("B - 01", "АУДИО_ВХОД", "СТАТУС") -
  ощущение технической/инженерной консоли.
- В центре - круглый аудио-визualizer: неровные радиальные полоски-"лучи" вокруг центра
  (как звуковая волна), поверх - тонкая пунктирная направляющая окружность.
- В самом центре - тёмный круг с обводкой и маленьким красным квадратом со скруглением
  (индикатор записи/стоп).
- Тонкая горизонтальная линия-разделитель, под ней обычным (не капсом) текстом статус-сообщение
  ("Установлено защищённое соединение. Захват входного потока...").
- Внизу по углам - технические показатели моноширинным шрифтом (таймер вида 00:00:12:81,
  частота дискретизации "44,1 кГц").

Не применять это к текущей ленте/карточкам сейчас - просто ориентир для будущего редизайна.

## Позиционирование и дизайн — не типичный сайт знакомств (2026-07-23)

Пользователь попросил зафиксировать общее направление проекта (пока без изменений в коде):

- **Цвета и элементы дизайна** — придерживаться общепринятых стандартов (то, чем пользуется
  большинство приличных продуктов: понятная типографика, доступные контрасты, привычные паттерны
  интерфейса), но при этом должен быть свой узнаваемый почерк — не просто копия чужого шаблона.
- **Это не сайт знакомств "для секса" и не сайт знакомств в привычном смысле вообще.**
  В первую очередь это что-то более деловое/обычное — площадка для общения обычных людей,
  которые оказались рядом (в аэропорту), а не про поиск романтики. Романтика может стать
  одним из направлений позже, но не как главная идея с самого начала.
- **Целевая аудитория** — обычные люди в аэропорту, которые хотят с кем-то пообщаться,
  а не искатели романтических/сексуальных знакомств.
- **По ощущению это должно быть чем-то средним между сайтом знакомств и социальной сетью** —
  не классический дейтинг-сайт и не соцсеть в чистом виде, а что-то своё между этими двумя.

**Почему это важно**: пользователь явно не хочет, чтобы проект визуально и по духу читался
как типичный дейтинг-сайт — это должно определять тон будущих решений по дизайну, копирайту
и функциям (например, не делать акцент на "паре"/свайпах-ромашках и т.п. типичных дейтинг-паттернах).
