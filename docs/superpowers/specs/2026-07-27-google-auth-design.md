# Вход через Google (первый кусок настоящего бэкенда)

Дата: 2026-07-27
Статус: согласовано с пользователем, готово к написанию плана реализации

## Зачем

Сейчас приложение целиком живёт в памяти браузера — нет ни настоящего входа, ни своей
анкеты, ни лайков, которые бы сохранялись. Это первый из четырёх запланированных кусков
работы над бэкендом (см. `notes.md` и обсуждение при брейнсторминге): вход и регистрация —
фундамент, без которого остальные куски (своя анкета, лента и лайки на настоящих данных,
переписка через базу) не имеют смысла.

Supabase уже подключён как бэкенд (клиент в `src/lib/supabase.ts`), поэтому вход делается
через встроенную в Supabase систему авторизации (Supabase Auth), а не пишется с нуля.
Способ входа — через Google (один клик, без своих паролей).

## Как это выглядит для человека

При открытии приложения — короткая проверка, есть ли уже вход (доля секунды, ничего не
показываем). Дальше два варианта:

- **Входа нет** — показывается экран с одной кнопкой «Войти через Google». После клика
  человек уходит на страницу Google, подтверждает вход, и возвращается обратно в
  приложение уже вошедшим.
- **Вход уже есть** — сразу переходим к тому, что было и раньше: заметка «Что вы ищете
  сейчас?», потом лента. Эта часть не меняется совсем.

Вход теперь запоминается по-настоящему — не пропадает при перезагрузке страницы, работает
с любого устройства, где человек вошёл в тот же Google-аккаунт. В «Аккаунт» добавляется
рабочая кнопка «Выйти».

## Технические детали

### `src/lib/useSession.ts` — знает, вошли мы или нет

```typescript
import { useEffect, useState } from 'react'
import type { Session } from '@supabase/supabase-js'
import { supabase } from './supabase'

export function useSession(): { session: Session | null; loading: boolean } {
  const [session, setSession] = useState<Session | null>(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    // onAuthStateChange сам присылает текущее состояние сразу при подписке
    // (событие INITIAL_SESSION) и дальше сообщает о каждом входе/выходе -
    // отдельный запрос на "проверь, есть ли сессия" не нужен.
    const { data } = supabase.auth.onAuthStateChange((_event, currentSession) => {
      setSession(currentSession)
      setLoading(false)
    })
    return () => data.subscription.unsubscribe()
  }, [])

  return { session, loading }
}
```

### `src/components/LoginScreen.tsx` — экран входа

Один экран с кнопкой «Войти через Google». Клик вызывает
`supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: window.location.origin } })`
— дальше Supabase и Google берут процесс на себя, включая обратное возвращение в
приложение с уже готовым входом (это делает библиотека `supabase-js` сама, без
дополнительного кода на нашей стороне).

### Изменения в `App.tsx`

`App` использует `useSession()`. Пока `loading === true` — рендерится пустой `<div className="h-full w-full bg-white" />`
(проверка идёт доли секунды, полноценный экран загрузки не нужен). Если `session === null` —
вместо `<HashRouter>` со всеми маршрутами рендерится `<LoginScreen />`. Если `session` есть —
всё остаётся как сейчас, без единого изменения в `RequireStatus`/маршрutах.

### Изменения в `AccountScreen.tsx`

Пункт «Помощь» в списке настроек остаётся как есть (не кнопка, декоративный), а рядом
добавляется настоящая кнопка «Выйти», вызывающая `supabase.auth.signOut()`. После выхода
`useSession()` сам заметит изменение (событие `SIGNED_OUT`) и `App.tsx` покажет `LoginScreen`.

## Настройка Google-входа (сделать один раз, руками)

Это делается в браузере, в панелях Google и Supabase — не в коде. Нужно сделать один раз,
до или во время реализации:

1. Зайти на [console.cloud.google.com](https://console.cloud.google.com/), создать новый
   проект (или выбрать существующий).
2. **APIs & Services → OAuth consent screen.** Тип — External. Заполнить название
   приложения и email. Статус оставить «Testing» — этого достаточно для личного проекта,
   проходить проверку Google не нужно.
3. На вкладке **Test users** добавить свой Google-аккаунт (и любой другой, с которого
   будете проверять вход) — пока приложение в статусе Testing, войти смогут только
   аккаунты из этого списка.
4. **Credentials → Create Credentials → OAuth client ID**, тип — Web application.
   - **Authorized JavaScript origins:** добавить `https://fly-app-eight.vercel.app` (рабочий
     сайт) и `http://localhost:5173` (адрес для локальной разработки — порт по умолчанию
     у `npm run dev` в этом проекте; если Vite выведет другой порт при запуске, добавить
     его тоже).
   - **Authorized redirect URIs:** адрес обратного вызова Supabase — он показан на
     странице провайдера Google в панели Supabase (следующий шаг), обычно вида
     `https://<project-ref>.supabase.co/auth/v1/callback`.
5. Скопировать **Client ID** и **Client Secret**, которые Google выдаст после создания.
6. В панели Supabase ([supabase.com/dashboard](https://supabase.com/dashboard)) → выбрать
   проект → **Authentication → Providers → Google** → включить, вставить Client ID и
   Client Secret → сохранить.

Без этих шагов кнопка «Войти через Google» будет уводить на страницу с ошибкой — так же,
как фича «Нужна идея?» раньше требовала ключа Anthropic.

## Обработка ошибок

Если человек отменит вход на странице Google, или что-то пойдёт не так по сети — Supabase
просто не создаст сессию, и человек останется на экране входа. Отдельного сообщения об
ошибке в этой первой версии не делаем (это не критичный сценарий, можно вернуться к нему
отдельно, если окажется нужным на практике) — YAGNI.

## Проверка

Живой вход через настоящий Google-аккаунт нельзя покрыть автотестом — это внешний сервис,
а не наши данные. Автотестов в этой фиче нет. Ручная проверка в браузере разделена на две
части:

- Я могу проверить, что кнопка «Войти через Google» действительно уводит на страницу
  Google (то есть код вызывает `signInWithOAuth` правильно) — дальше сам вход через
  реальный Google-аккаунт нужно будет один раз пройти тебе самому, потому что для этого
  нужен доступ к твоему Google-аккаунту.
- После первого успешного входа: перезагрузить страницу (вход должен сохраниться),
  нажать «Выйти» в «Аккаунт» (должно вернуть на экран входа).

## Новые технические зависимости

Никаких новых npm-пакетов — `@supabase/supabase-js` уже установлен. Новых переменных
окружения в коде тоже нет: настройка Google живёт в панелях Supabase/Google, а не в
`.env.local`.
