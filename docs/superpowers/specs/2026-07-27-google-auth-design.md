# Вход по ссылке на почту (первый кусок настоящего бэкенда)

Дата: 2026-07-27, обновлено 2026-07-27
Статус: согласовано с пользователем, реализовано

## Зачем

Сейчас приложение целиком живёт в памяти браузера — нет ни настоящего входа, ни своей
анкеты, ни лайков, которые бы сохранялись. Это первый из четырёх запланированных кусков
работы над бэкендом (см. `notes.md` и обсуждение при брейнсторминге): вход и регистрация —
фундамент, без которого остальные куски (своя анкета, лента и лайки на настоящих данных,
переписка через базу) не имеют смысла.

Supabase уже подключён как бэкенд (клиент в `src/lib/supabase.ts`), поэтому вход делается
через встроенную в Supabase систему авторизации (Supabase Auth), а не пишется с нуля.

**Обновление:** первая версия этой спеки описывала вход через Google. При реализации
выяснилось, что регистрация в Google Cloud (нужна, чтобы включить вход через Google)
недоступна для аккаунтов из России из-за санкций — это ограничение самого Google, не
техническая деталь, которую можно обойти настройкой. Переключились на **вход по ссылке,
присланной на почту** (без пароля) — он делается целиком внутри Supabase, без внешних
сервисов и без гео-ограничений.

## Как это выглядит для человека

При открытии приложения — короткая проверка, есть ли уже вход (доля секунды, ничего не
показываем). Дальше два варианта:

- **Входа нет** — экран с полем для почты и кнопкой «Прислать ссылку для входа». После
  клика — сообщение «Проверьте почту». Человек открывает письмо, переходит по ссылке и
  возвращается в приложение уже вошедшим.
- **Вход уже есть** — сразу переходим к тому, что было и раньше: заметка «Что вы ищете
  сейчас?», потом лента. Эта часть не меняется совсем.

Вход запоминается по-настоящему — не пропадает при перезагрузке страницы, работает с
любого устройства, где открыть ту же ссылку. В «Аккаунт» есть рабочая кнопка «Выйти».

## Технические детали

### `src/lib/useSession.ts` — знает, вошли мы или нет

Не меняется способом входа вообще — этот хук просто следит за состоянием сессии в
Supabase, ему не важно, каким способом она была получена (почта, Google или что угодно
ещё в будущем).

```typescript
import { useEffect, useState } from 'react'
import type { Session } from '@supabase/supabase-js'
import { supabase } from './supabase'

export function useSession(): { session: Session | null; loading: boolean } {
  const [session, setSession] = useState<Session | null>(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    // onAuthStateChange сам присылает текущее состояние сразу при подписке
    // (событие INITIAL_SESSION) и дальше сообщает о каждом входе/выходе -
    // отдельный запрос на "проверь, есть ли сессия" не нужен.
    const { data } = supabase.auth.onAuthStateChange((_event, currentSession) => {
      setSession(currentSession)
      setLoading(false)
    })
    return () => data.subscription.unsubscribe()
  }, [])

  return { session, loading }
}
```

### `src/components/LoginScreen.tsx` — экран входа

Поле для почты + кнопка «Прислать ссылку для входа». Клик вызывает

```typescript
supabase.auth.signInWithOtp({
  email: trimmedEmail,
  options: { emailRedirectTo: window.location.origin },
})
```

— Supabase сам отправляет письмо со ссылкой; отдельно регистрировать человека не нужно
(`signInWithOtp` создаёт аккаунт при первом обращении и входит в него при последующих —
регистрация и вход это один и тот же экран). После отправки экран переключается в
состояние «Проверьте почту» (локальное состояние `sent`, без сохранения между
перезагрузками — если обновить страницу, форма появится заново, это нормально).

**Технический нюанс, который проверили отдельно:** ссылка из письма возвращает человека в
приложение с данными о входе в адресе страницы (после `#` или `?`, в зависимости от
настроек). Этот проект использует `HashRouter` (адреса вида `.../#/лента`), поэтому в
принципе есть риск конфликта — оба механизма читают часть адреса после `#`. На практике
конфликта нет: пока это подтверждается (`useSession` -> `loading`), приложение показывает
пустой экран и **не рендерит `HashRouter` вообще** — он появляется только после того, как
Supabase уже закончил разбирать адрес и обязательно подчистил его. `HashRouter` попросту
никогда не видит "сырой" адрес со служебными данными входа.

### Изменения в `App.tsx`

Не меняются относительно первой версии. `App` использует `useSession()`. Пока
`loading === true` — рендерится пустой `<div className="h-full w-full bg-white" />`. Если
`session === null` — вместо `<HashRouter>` со всеми маршрутами рендерится `<LoginScreen />`.
Если `session` есть — всё остаётся как сейчас, без единого изменения в
`RequireStatus`/маршрутах.

### Изменения в `AccountScreen.tsx`

Не меняются относительно первой версии. Рабочая кнопка «Выйти», вызывающая
`supabase.auth.signOut()`. После выхода `useSession()` сам заметит изменение (событие
`SIGNED_OUT`) и `App.tsx` покажет `LoginScreen`.

## Настройка в Supabase (сделать один раз, руками)

Google Cloud больше не нужен вообще. Единственная ручная настройка — в панели Supabase:

1. [supabase.com/dashboard](https://supabase.com/dashboard) → выбрать проект →
   **Authentication → URL Configuration**.
2. **Site URL** — рабочий адрес сайта, `https://fly-app-eight.vercel.app`.
3. **Redirect URLs** — добавить туда же `https://fly-app-eight.vercel.app` и
   `http://localhost:5173` (адрес для локальной разработки — порт по умолчанию у
   `npm run dev` в этом проекте). Это единственные адреса, куда Supabase разрешит
   вернуть человека после перехода по ссылке из письма.
4. Сохранить.

По умолчанию у Supabase есть встроенная отправка писем (без настройки своего почтового
сервера) — этого достаточно для личного проекта; если писем окажется слишком много для
встроенного лимита, можно будет подключить свой SMTP отдельно, но сейчас это не нужно.

## Обработка ошибок

Если человек введёт неверный адрес почты или письмо не дойдёт по сети — Supabase просто не
создаст сессию, человек останется на экране с формой (или увидит стандартную ошибку
Supabase, если она есть). Отдельного красивого сообщения об ошибке в этой первой версии не
делаем — YAGNI, можно будет добавить позже, если понадобится на практике.

## Проверка

Живое получение письма и переход по ссылке нельзя покрыть автотестом — это внешний почтовый
сервис, а не наши данные. Автотестов в этой фиче нет. Ручная проверка в браузере разделена
на две части:

- Я могу проверить, что форма корректно вызывает `signInWithOtp` (без ошибки в консоли) и
  переключается в состояние «Проверьте почту».
- Сам переход по присланной ссылке и успешный вход нужно один раз проверить тебе самому,
  потому что для этого нужен доступ к твоей настоящей почте.

## Новые технические зависимости

Никаких новых npm-пакетов — `@supabase/supabase-js` уже установлен. Новых переменных
окружения в коде тоже нет: настройка живёт в панели Supabase (URL Configuration), а не в
`.env.local`.
