# Настоящие лайки и совпадения (последний из четырёх кусков бэкенда)

Дата: 2026-07-28
Статус: реализуется

## Зачем

Вход, своя публикация, своя анкета и настоящая лента уже сделаны. Последний
из четырёх запланированных кусков — лайки и совпадения на настоящих данных
вместо старого правила «совпадение случается, если у тестовой анкеты стоит
`interestedInYou`». Сам текст переписки (сообщения в чате) остаётся локальным
и в этот раз не трогается — отдельная задача на будущее.

## Как это выглядит для человека

Кнопка лайка возвращается на карточки в ленте (в прошлом куске её скрыли —
лайкать было некого по-настоящему). Если человек уже лайкнул кого-то раньше
(например, был лайк, потом перезагрузили страницу) — кнопка сразу показывает
это состояние, повторный лайк не отправляется.

Экран «Сообщения» показывает настоящие совпадения — тех, кого лайкнул(а) ты
и кто лайкнул(а) в ответ, по данным из базы, а не из памяти приложения.
Сам текст переписки по-прежнему не сохраняется (как и раньше — это
отдельный следующий шаг за пределами этого куска).

## Технические детали

### Новая таблица `likes`

```sql
create table public.likes (
  liker_id uuid not null references auth.users (id) on delete cascade,
  liked_id uuid not null references auth.users (id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (liker_id, liked_id),
  check (liker_id <> liked_id)
);

alter table public.likes enable row level security;

-- Видно только свои лайки (кого лайкнул я, и кто лайкнул меня) - второе нужно,
-- чтобы вычислять совпадения.
create policy "likes_select_own_or_received" on public.likes
  for select
  to authenticated
  using ( (select auth.uid()) = liker_id or (select auth.uid()) = liked_id );

-- Ставить лайк можно только от своего имени
create policy "likes_insert_own" on public.likes
  for insert
  to authenticated
  with check ( (select auth.uid()) = liker_id );

-- Как и раньше (см. LESSONS.md) - явно забираем платформенные дефолтные права
-- прежде чем выдавать ровно то, что нужно.
revoke all on public.likes from anon, authenticated;
grant select, insert on public.likes to authenticated;
```

`primary key (liker_id, liked_id)` не даёт лайкнуть одного и того же человека
дважды (повторная попытка вставки — ошибка, не дубликат). `check (liker_id <>
liked_id)` — нельзя лайкнуть самого себя (в интерфейсе такое и так
невозможно, своя анкета не показывается себе в ленте, но проверка в базе —
подстраховка, а не лишняя). Без update/delete-политик — отмена лайка не
входит в этот кусок (YAGNI, как и раньше).

### `Profile` — небольшая правка типа

`interestedInYou?: boolean` (задел под мок-механику совпадений) убирается -
он никогда не заполнялся настоящими данными и был нужен только для старого
способа находить совпадения. Вместо него - `likedByMe: boolean` (не
необязательное - вычисляется всегда): лайкнул ли уже я этого человека,
нужно кнопке лайка, чтобы не спрашивать дважды.

### `src/lib/useFeedProfiles.ts` — добавляется `likedByMe`

Один дополнительный запрос (`likes` где `liker_id` = я) параллельно с
запросом публикаций, результат кладётся в каждую анкету как `likedByMe`.

### `src/lib/useMatches.ts` — новый файл

По аналогии с `useFeedProfiles`: два запроса (кого лайкнул я, кто лайкнул
меня), пересечение - это совпадения, дальше публикации+анкеты для этих
людей (тот же принцип склейки, что в `useFeedProfiles`, но без общего кода
между ними - две похожие, но независимые небольшие функции; не выношу
в общий хелпер ради этого куска, чтобы не трогать уже проверенный
`useFeedProfiles` лишний раз).

### `ProfileCard.tsx` — лайк настоящий и с памятью

- Начальное состояние кнопки (`liked`) берётся из `profile.likedByMe`, а не
  всегда `false`.
- Клик по уже лайкнутой карточке — ничего не делает (без повторной отправки).
- `onLike` становится асинхронным (`Promise<void>`) - при неудаче (нет сети)
  визуально откатываем лайк обратно, без отдельного текста ошибки (это
  маленькая кнопка на карточке в списке, не отдельная форма - тихий откат
  достаточен).

### Упрощение: `matches`/`onLike` больше не идут через весь `App.tsx`

Раньше лайк «поднимался» из `ProfileCard` → `FeedScreen` → контекст `AppShell`
→ `App.tsx` (там жило состояние `matches`) → обратно вниз в `MessagesScreen`.
Раз совпадения теперь по-настоящему хранятся в базе, а не в памяти
приложения, `MessagesScreen` может просто сам спросить `useMatches` -
как `FeedScreen` сам спрашивает `useFeedProfiles`. Значит:

- `App.tsx`: `matches`/`handleLike` убираются полностью.
- `AppOutletContext`/`AppShellProps`: `matches`/`onLike` убираются, остаётся
  только `currentUserId`.
- `FeedScreen.tsx`: заводит свою функцию лайка (вставка в `likes` через
  `supabase`, используя `currentUserId` из контекста) и передаёт её в
  `ProfileCard` как `onLike`.
- `MessagesScreen.tsx`: вызывает `useMatches(currentUserId)` вместо чтения
  `matches` из контекста.

## Обработка ошибок

Лайк не сохранился (нет сети) - кнопка визуально откатывается назад (см.
`ProfileCard.tsx` выше), можно попробовать ещё раз. Повторная попытка
лайкнуть уже лайкнутого - блокируется на уровне интерфейса (клик по уже
лайкнутой карточке ничего не делает), а не только в базе.

## Проверка

Ручная, как и раньше: два аккаунта лайкают друг друга по очереди - после
второго лайка (взаимного) у обоих в «Сообщениях» должно появиться
совпадение. Один аккаунт лайкает, другой - нет: совпадения быть не должно.
Автотестов нет - та же причина, что и в предыдущих кусках (реальный поход
в Supabase).

## Что не входит в этот кусок

- Отмена лайка.
- Экран «Кто меня лайкнул» в Аккаунте (остаётся декоративной заглушкой).
- Сохранение текста переписки в базу.

## Новые технические зависимости

Нет.
