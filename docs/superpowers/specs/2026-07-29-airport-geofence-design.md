# "Работает только в аэропорту" — геолокация (главная задумка проекта)

Дата: 2026-07-29
Статус: реализуется

## Зачем

Все предыдущие куски делали типовую инфраструктуру сайта знакомств (вход,
анкета, лента, лайки, сообщения) — обычные вещи, которые есть у любого
подобного приложения. Единственное, что реально отличает этот проект от
шаблонного сайта знакомств — идея "работает только внутри аэропорта"
(зафиксирована в notes.md с самого начала проекта). До сих пор это никак не
проверялось технически — приложение работает откуда угодно. Этот кусок
добавляет настоящую проверку.

## Что уже было решено раньше (нашлось в коде)

`src/lib/liveContext.ts` уже использует захардкоженные координаты аэропорта
Шереметьево (SVO, 55.9736, 37.4125) для запроса погоды в подсказках статуса,
с явным комментарием "приложение пока не определяет геолокацию человека".
Строка статуса в `AppShell.tsx` тоже показывает код "SVO". То есть выбор
конкретного аэропорта для этого проекта был сделан раньше, неявно — просто
не было технической проверки геопозиции. Этот кусок реализует то, на что
уже давно было явно рассчитано.

## Что именно требует нахождения в аэропорту

Обсудили с пользователем: только **первая публикация заметки** (разовый
экран `/new`) и **сама лента** (просмотр чужих публикаций). Сообщения
(готовые совпадения, продолжение переписки) и Аккаунт работают из любого
места — человек мог уже улететь, а переписка с совпадением продолжается.

## Как это выглядит для человека

При заходе на ленту или на экран первой публикации браузер один раз (как
для камеры/микрофона) спрашивает разрешение показать местоположение —
стандартный системный диалог, отдельный экран-объяснение перед ним не
рисуем (он не нужен: сам браузер объясняет, зачем сайту это разрешение).

- **Рядом с аэропортом** (в пределах ~5 км от координат SVO — это покрывает
  весь комплекс терминалов, а не точку) — экран показывается как обычно.
- **Далеко** — вместо ленты/публикации показывается объясняющий экран:
  "Это приложение работает только в аэропорту Шереметьево (SVO). Судя по
  местоположению, сейчас вы не там." + кнопка "Проверить снова".
- **Не дали доступ к геолокации** — свой текст: "Нужен доступ к
  местоположению, чтобы проверить, что вы в аэропорту" + кнопка "Проверить
  снова" (повторно откроет системный диалог, если браузер это позволяет —
  в большинстве браузеров второй раз просто отдаёт сохранённое решение,
  тогда придётся разрешить через настройки сайта в браузере вручную - это
  ограничение браузера, не то, что можно обойти кодом).
- **Браузер не поддерживает геолокацию** (очень редкий случай) - похожий
  экран с соответствующим текстом.

Проверка происходит один раз при открытии экрана (как лента и совпадения -
без постоянного отслеживания местоположения, то же решение, что и раньше
в этом проекте: не усложняем без явной необходимости).

## Технические детали

### `src/lib/geo.ts` — новый файл, чистая логика расстояния

```typescript
// Формула гаверсинуса - стандартный способ посчитать расстояние между двумя
// точками на земном шаре по широте/долготе (в километрах).
export function getDistanceKm(lat1: number, lon1: number, lat2: number, lon2: number): number {
  const EARTH_RADIUS_KM = 6371
  const toRad = (deg: number) => (deg * Math.PI) / 180
  const dLat = toRad(lat2 - lat1)
  const dLon = toRad(lon2 - lon1)
  const a =
    Math.sin(dLat / 2) ** 2 + Math.cos(toRad(lat1)) * Math.cos(toRad(lat2)) * Math.sin(dLon / 2) ** 2
  const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a))
  return EARTH_RADIUS_KM * c
}
```

Стандартная, широко известная формула - не изобретаем свою. Покрывается
юнит-тестом на паре городов с известным расстоянием (Москва-Питер и т.п.) -
это чистая математика без похода в сеть, TDD применим так же, как для
`getAgeWord`.

```typescript
// Аэропорт, для которого сейчас работает приложение. Один захардкоженный

// уже использовались в liveContext.ts для погоды. Список из нескольких

export const AIRPORT = {
  code: 'SVO',
  name: 'Шереметьево',
  latitude: 55.9736,
  longitude: 37.4125,
  // Радиус, в который должен попасть человек, чтобы считаться "в аэропорту" -

```

`liveContext.ts` меняется, чтобы брать координаты отсюда вместо собственных
констант - одно место истины вместо двух.

### `src/lib/useAirportPresence.ts` — новый хук

Оборачивает `navigator.geolocation.getCurrentPosition` (встроенный API
браузера, тот же, которым пользуются карты и погодные сайты - не пишем
свою геолокацию) в React-состояние с пятью исходами:

```typescript
export type AirportPresenceStatus =
  | 'checking'
  | 'at-airport'
  | 'not-at-airport'
  | 'permission-denied'
  | 'unsupported'
  | 'error'

export function useAirportPresence(): {
  status: AirportPresenceStatus
  distanceKm: number | null
  retry: () => void
}
```

`retry` увеличивает внутренний счётчик попыток, что перезапускает
`useEffect` и заново вызывает `getCurrentPosition`.

### `src/components/NotAtAirportScreen.tsx` — новый экран

Полноэкранный вид, по образцу `LoginScreen.tsx` - не часть `AppShell`, без
строки статуса и нижней навигации. Принимает `status`, `distanceKm`,
`onRetry` - показывает подходящий текст и кнопку "Проверить снова" (см.
тексты выше).

### `App.tsx` — новый компонент-охранник `RequireAirport`

По образцу уже существующего `RequireStatus`, но не редиректит (некуда -
это не отдельный маршрут, а состояние прямо на месте), а показывает
`NotAtAirportScreen` вместо содержимого:

```typescript
function RequireAirport({ children }: { children: ReactNode }) {
  const { status, distanceKm, retry } = useAirportPresence()
  if (status === 'checking') return <div className="h-full w-full bg-white" />
  if (status !== 'at-airport') return <NotAtAirportScreen status={status} distanceKm={distanceKm} onRetry={retry} />
  return <>{children}</>
}
```

Оборачивает только `FeedScreen` (маршрут `/`) и `CreateStatusScreen` на
`/new` (когда заметки ещё нет) - `MessagesScreen`/`AccountScreen` не
трогаются, работают как раньше из любого места. Редактирование уже
опубликованной заметки через `AccountScreen` (сделано в прошлом куске) -
тоже не требует аэропорта, это часть Аккаунта, а не первой публикации.

## Обработка ошибок

Уже часть основного дизайна (см. "Как это выглядит для человека") -
отдельного раздела не требуется, все пять состояний `useAirportPresence`
имеют свой понятный экран, ни одно не оставляет человека перед пустым
экраном без объяснения.

## Проверка

- `getDistanceKm` - автотест (юнит-тест на известных парах координат).
- Живая проверка геолокации: браузер не даёт по-настоящему притвориться в
  другой точке без обмана системы - для разработки используем встроенный в
  Chrome DevTools "Sensors → Location" (подставляет координаты по запросу
  страницы к geolocation API) - стандартный инструмент разработчика, не
  часть кода приложения. Проверить: координаты Шереметьево → пускает,
  координаты, например, центра Москвы → показывает "не в аэропорту".
- Проверить путь "отказался дать доступ" (в DevTools можно заблокировать
  разрешение) - должен показать понятный экран, а не сломаться.

## Что не входит в этот кусок

- Несколько аэропортов на выбор - только Шереметьево сейчас.
- Постоянное отслеживание местоположения, пока сидишь в ленте (проверка
  только при открытии экрана).
- Кнопка "притвориться, что я в аэропорту" внутри самого приложения -
  тестируется через инструменты браузера, не отдельной фичей в коде.

## Новые технические зависимости

Нет - `navigator.geolocation` встроен в браузер.
