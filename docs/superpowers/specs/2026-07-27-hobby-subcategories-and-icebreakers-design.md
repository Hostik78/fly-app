# Конкретные хобби и подсказки для начала разговора

Дата: 2026-07-27
Статус: согласовано с пользователем, готово к написанию плана реализации

## Зачем

Сейчас у анкет есть только одна широкая категория «Увлечения» — конкретное хобби (велосипед,
кино и т.п.) существует лишь как часть свободного текста фразы, никак не структурировано.
Из заметки в `notes.md` (2026-07-21): «Увлечения» должны раскрываться в список конкретных
хобби, а ИИ (или готовый набор) — предлагать варианты, с чего начать разговор, в зависимости
от выбранного увлечения (например, для «велосипеды» — спросить «шоссейный или горный?»).

Эта фича полностью на данных и интерфейсе — без единого сетевого запроса. Решили, что живая
генерация нейросетью тут не нужна (в отличие от фичи «Нужна идея?»), потому что сами вопросы
привязаны к хобби, а не к меняющемуся контексту вроде погоды или времени суток.

## Изменения в данных анкеты

В `src/data/profiles.ts`:
- Новый тип `HobbyId` (объединение восьми id из таблицы выше) — живёт в `hobbies.ts`, а не
  в `profiles.ts`, потому что это данные о хобби, а не об анкете как таковой.
- У `Profile` появляется необязательное поле `hobby?: HobbyId`. Заполняется только у анкет
  с `category: 'hobbies'`. У анкет с другими категориями это поле не используется.
- Две тестовые анкеты категории `hobbies` в текущем списке получают конкретное значение:
  анкета про велосипед → `hobby: 'cycling'`, анкета про фильм → `hobby: 'movies'`.

## Второй ряд фильтров в ленте (`FeedScreen.tsx`)

Когда верхний фильтр (`activeFilter`) равен `'hobbies'` — под обычным рядом фильтров-таблеток
появляется второй, поменьше: «Все» + восемь хобби из списка. Это отдельное состояние
(`activeHobby`, по умолчанию `'all'`), не связанное с состоянием верхнего фильтра напрямую —
просто второй ряд не рендерится, если `activeFilter !== 'hobbies'`.

Видимые анкеты фильтруются в два шага: сначала по `activeFilter` (как сейчас), затем — если
`activeFilter === 'hobbies'` и `activeHobby !== 'all'` — дополнительно по `profile.hobby ===
activeHobby`.

У остальных пяти категорий второго ряда нет и не будет — фича не трогает их.

## Выбор своего хобби при создании заметки (`CreateStatusScreen.tsx`)

Если выбранная категория — `'hobbies'`, под рядом категорий появляется точно такой же ряд
восьми хобби (плюс без «Все» — тут это не фильтр, а обязательный выбор одного варианта).
Выбранное хобби хранится в новом состоянии экрана (`hobby: HobbyId | null`, по умолчанию `null`).

Кнопка «Опубликовать» становится доступна только когда: текст заметки не пустой, **и** —
если категория `'hobbies'` — хобби выбрано. Для остальных категорий условие про хобби не
действует (там этого поля просто нет).

`hobby` передаётся наружу тем же способом, что сейчас `quote`/`category` — через колбэк
`onSubmit`. Как и `quote`/`category` сегодня, значение пока никуда не сохраняется по-настоящему
(`App.tsx` его отбрасывает) — приложение ещё не хранит профиль самого человека. Это не
недоделанность конкретно этой фичи, а текущее состояние всего прототипа.

## Подсказки для начала разговора (`ChatScreen.tsx`)

Новый файл `src/data/icebreakers.ts` — чистые данные, без сети: `Record<HobbyId, string[]>`,
по 2 коротких вопроса на каждое хобби (например, для `cycling`: «Шоссейный или горный?» и
«На сколько километров у вас обычно вылазки?»), плюс функция `getIcebreakers(hobby: HobbyId):
string[]`.

В `ChatScreen.tsx`: подсказки показываются, только если у собеседника (`match`) есть
`category === 'hobbies'` и заполненное `hobby`, **и** среди `messages` ещё нет ни одного
сообщения с `from === 'me'` (то есть человек ещё не написал первое сообщение сам). Как только
появляется первое сообщение «от меня» — подсказки просто перестают показываться при
следующей отрисовке (никакого отдельного состояния «скрыто навсегда» не нужно).

Внешний вид — короткий ряд из 2 подсказок над полем ввода, тем же визуальным языком, что и
инстант-варианты в `SuggestionPanel` (белые кнопки на сером фоне, `rounded-fly-md`). Тап по
подсказке вставляет её текст в поле ввода (`draft`), не отправляя сообщение — человек всё
ещё может отредактировать перед отправкой. Иконка-искорка не нужна: этот источник не помечает
«придумано ИИ», в отличие от «Нужна идея?» — здесь вообще нет ИИ-варианта, только готовый набор.

## Обработка ошибок

Сетевых вызовов в этой фиче нет вообще — соответственно, нет и сценариев таймаута/недоступности
сервиса, которые нужно было бы обрабатывать. Единственный «пустой» случай — хобби не выбрано
при создании заметки: это уже покрыто требованием к кнопке «Опубликовать» выше.

## Проверка (тесты)

По аналогии с первым тестом в проекте (`suggestionTemplates.test.ts`): новый тест
`icebreakers.test.ts` для чистой функции `getIcebreakers` — проверяет, что для каждого хобби
из списка возвращается непустой список из 2 вопросов, и что среди них нет ни `undefined`,
ни пустых строк.

Остальные три места (второй ряд фильтров в ленте, выбор хобби при создании заметки, показ
подсказок в переписке) — это интерфейс без своей логики принятия решений за пределами простых
условий рендеринга, тестами не покрываем — так же, как и `SuggestionPanel`/`CreateStatusScreen`
в прошлой фиче.

## Новые технические зависимости

Никаких — фича не добавляет ни новых npm-пакетов, ни переменных окружения, ни серверных
функций.
