# Настоящий текст переписки

Дата: 2026-07-29
Статус: реализуется

## Зачем

Вход, публикация, анкета, лента и лайки/совпадения уже настоящие. Последнее,
что всё ещё живёт только в памяти браузера — сам текст переписки в чате:
обновил страницу — переписка пропала, хотя совпадение осталось. Это
закрывает этот пробел.

## Как это выглядит для человека

Ничего не меняется во внешнем виде экрана переписки — только теперь текст
сохраняется по-настоящему: обновил страницу, зашёл с другого устройства -
переписка на месте. Список совпадений в «Сообщениях» под именем каждого
человека показывает его фразу из анкеты (как и сейчас при первом открытии
пустого чата) - настоящий "последний написанный текст" в списке не
показываем в этот раз (см. "Что не входит").

## Технические детали

### Новая таблица `messages`

```sql
create table public.messages (
  id uuid primary key default gen_random_uuid(),
  sender_id uuid not null references auth.users (id) on delete cascade,
  recipient_id uuid not null references auth.users (id) on delete cascade,
  text text not null check (char_length(trim(text)) > 0),
  created_at timestamptz not null default now(),
  check (sender_id <> recipient_id)
);

alter table public.messages enable row level security;

-- Видно сообщения, где я отправитель или получатель
create policy "messages_select_own" on public.messages
  for select
  to authenticated
  using ( (select auth.uid()) = sender_id or (select auth.uid()) = recipient_id );

-- Писать можно только от своего имени, и только тому, с кем есть настоящее
-- взаимное совпадение - проверка прямо в базе, не только в интерфейсе
-- (в интерфейсе экран чата и так открывается только для совпадений).
create policy "messages_insert_if_matched" on public.messages
  for insert
  to authenticated
  with check (
    (select auth.uid()) = sender_id
    and exists (select 1 from public.likes where liker_id = sender_id and liked_id = recipient_id)
    and exists (select 1 from public.likes where liker_id = recipient_id and liked_id = sender_id)
  );

revoke all on public.messages from anon, authenticated;
grant select, insert on public.messages to authenticated;
```

### `src/lib/useConversation.ts` — новый хук

Загружает сообщения между текущим человеком и конкретным собеседником
(`.or()` с двумя направлениями: я → он, он → я), плюс функция отправки
(вставка в базу + добавление в список на экране сразу, без перезагрузки
всего списка).

### `ChatScreen.tsx` — сам грузит переписку

Раньше получал `messages`/`onSend` пропсами от `MessagesScreen` (которая
хранила всё в памяти). Теперь сам вызывает `useConversation` (по образцу
`FeedScreen`/`MessagesScreen`, которые уже сами спрашивают у базы то, что
им нужно) - `currentUserId` берёт из `useOutletContext`, как и другие
экраны. Пропсы остаются только `match`/`onBack`.

Если сообщений ещё нет (`loading === false`, `messages.length === 0`) -
показывается та же самая фраза-заглушка из анкеты собеседника
(`match.quote`), что и сейчас - просто не сохраняется в базу, только для
показа, пока не написали первое настоящее сообщение.

### `MessagesScreen.tsx` — упрощается

`messagesByMatch`/`getMessages`/`handleSend` убираются - это всё уехало в
`ChatScreen`. В строке предпросмотра под именем в списке совпадений вместо
"последнего сообщения" (что потребовало бы отдельного запроса на каждое
совпадение) показывается `match.quote` - то же самое, что видно при первом
открытии пустого чата. Настоящий "текст последнего сообщения" в списке -
осознанно не в этот раз (см. ниже).

## Обработка ошибок

Не отправилось (нет сети) - `sendMessage` выбрасывает ошибку, `ChatScreen`
её ловит: текст остаётся в поле ввода (не потерялся), короткое сообщение
под полем, как в остальных формах этого проекта.

## Проверка

Ручная: два аккаунта с совпадением переписываются - обновить страницу у
обоих, переписка должна остаться. Третий (без совпадения с ними) не должен
иметь возможность написать напрямую через API (проверяется insert-политикой
в базе). Автотестов нет - та же причина, что и в предыдущих кусках.

## Что не входит

- "Текст последнего сообщения" в списке совпадений (показываем фразу из
  анкеты вместо этого - YAGNI, отдельный запрос на каждое совпадение того
  не стоит сейчас).
- Отметки "прочитано"/непрочитанные сообщения.
- Живое обновление чата, пока сидишь в нём (сообщения появляются при
  открытии экрана, как и лента/совпадения - тот же принцип, что уже
  выбрали для них).
