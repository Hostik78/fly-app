# Статусы сообщений, "был в сети" и профиль из чата — дизайн-спека

**Статус**: одобрено пользователем (архитектура обсуждена и подтверждена, вид
профиля выбран — всплывающая карточка поверх чата).

## Цель

Три доработки экрана переписки (ChatScreen):
1. Статус моих сообщений: Отправлено / Доставлено / Просмотрено.
2. В шапке чата — не статичное "Не в сети", а "Был(а) в сети N назад", когда
   человек не в сети прямо сейчас.
3. Клик по аватару/имени в шапке — всплывающая карточка анкеты поверх чата.

## 1. Статусы сообщений

**Честное упрощение по сравнению с WhatsApp**: у WhatsApp "доставлено" приходит
от Apple/Google push-серверов (мы физически не можем это узнать с веб-сайта).
Здесь "доставлено" значит "долетело до браузера собеседника", а не "до его
телефона через ОС".

**Хранение**: два новых поля прямо на строке сообщения (`messages`), а не
отдельная таблица — отдельная таблица нужна для групповых чатов (там у одного
сообщения статус разный для каждого из многих получателей), у нас чат всегда
1-на-1, поэтому один получатель = одно поле на сообщение, этого достаточно.

```sql
alter table public.messages
  add column delivered_at timestamptz,
  add column read_at timestamptz;

-- Обновлять эти два поля может только получатель (не отправитель, не автор
-- текста) - column-level grant не даёт даже теоретически переписать сам текст
-- сообщения через ту же лазейку.
grant update (delivered_at, read_at) on public.messages to authenticated;

create policy "messages_update_receipt" on public.messages
  for update
  to authenticated
  using ( (select auth.uid()) = recipient_id )
  with check ( (select auth.uid()) = recipient_id );
```

**Логика (на стороне получателя, в useConversation.ts)**:
- `delivered_at` проставляется, как только сообщение оказалось у меня на
  экране — либо сразу при открытии чата (первая загрузка истории), либо живым
  событием (Realtime INSERT), если чат уже открыт.
- `read_at` проставляется в тот же момент, ЕСЛИ вкладка браузера видима и в
  фокусе (`document.visibilityState === 'visible'`) — стандартный Page
  Visibility API, не своя логика. Если сообщение пришло, пока вкладка свёрнута
  или человек переключился на другое приложение — `delivered_at` есть,
  `read_at` — нет, пока не вернутся в вкладку (слушаем `visibilitychange`).

**Логика (на стороне отправителя, тоже в useConversation.ts)**: чтобы СВОИ же
статусы обновлялись на экране без перезахода, подписываемся дополнительно на
Realtime UPDATE (не только INSERT, как сейчас) с фильтром `sender_id=eq.<я>` —
когда получатель проставляет delivered/read, у меня на экране статус меняется
сам.

**Отображение**: `ChatMessage` получает поля `deliveredAt`/`readAt`. Текст под
пузырём (`text-fly-gray`, мелким) — только на своих сообщениях (`from==='me'`):
"Отправлено" (есть id, оба поля пустые) → "Доставлено" (delivered_at есть,
read_at пустой) → "Просмотрено" (read_at есть).

## 2. "Был(а) в сети N назад"

Сейчас "онлайн" - только список тех, кто прямо сейчас подключён (Supabase
Realtime Presence, см. useOnlinePresence.ts) - ничего не помнит после выхода.

**Хранение**: одно новое поле в `profiles` (не отдельная таблица — presence и
так уже частично живёт в самом профиле человека по духу, отдельная таблица
была бы оправдана только если бы это поле часто менялось конкурентно от разных
источников, а тут пишет только сам человек про самого себя):

```sql
alter table public.profiles add column last_seen_at timestamptz;
```

Права уже подходят как есть — `profiles_update_own` (обновлять только свою
строку) и `profiles_select_all_authenticated` (все видят анкеты всех) уже
существуют, новых grant/policy не нужно.

**Обновление**: в useOnlinePresence.ts (уже подключён один раз на всё
приложение, в AppShell) — раз в 60 секунд, пока хук примонтирован, записывать
`last_seen_at = now()` в свою же строку профиля. Простой "пинг по таймеру", а
не попытка поймать момент отключения (тот ненадёжен — закрытие вкладки не
гарантирует, что успеет отправиться сетевой запрос).

**Отображение**: новая функция `src/lib/relativeTime.ts` -
`formatLastSeen(lastSeenAt: string): string` → "N минут назад" / "N часов
назад" / "вчера" / "N дней назад" (с русским склонением, по образцу
`pluralize.ts`). ChatScreen: если `isOnline` - как сейчас, "Онлайн"; иначе -
`formatLastSeen(match.lastSeenAt)`, если оно вообще есть (человек мог ни разу
не зайти после этого обновления - тогда просто "Не в сети", без чисел).

`Profile` (data/profiles.ts) получает необязательное поле `lastSeenAt` -
заполняется в useMatches.ts (там, где грузится сама анкета собеседника).

## 3. Всплывающая карточка анкеты

Новый компонент `ProfileDetailSheet.tsx` — тонкая обёртка: затемнение фона
(клик мимо - закрыть) + сама `ProfileCard` внутри, отрендеренная крупнее
(без урезанной ширины списка). Переиспользует существующий компонент карточки
как есть, не копирует вёрстку. Внутри ChatScreen — состояние
`showProfile: boolean`, открывается кликом по аватару/имени в шапке.

## Список файлов

1. **Миграция** (`supabase/migrations/`) — оба `alter table` выше, одним
   файлом или двумя по порядку (messages, потом profiles).
2. **src/lib/database.types.ts** — перегенерировать после миграции
   (`supabase gen types typescript --linked`), не редактировать руками.
3. **src/lib/useConversation.ts** — delivered/read логика, доп. Realtime
   подписка на UPDATE.
4. **src/lib/useOnlinePresence.ts** — heartbeat `last_seen_at` раз в 60 сек.
5. **src/lib/useMatches.ts** — подтягивать `last_seen_at` вместе с остальными
   полями анкеты.
6. **src/lib/relativeTime.ts** (новый) — `formatLastSeen`.
7. **src/data/profiles.ts** — `Profile.lastSeenAt?: string`.
8. **src/components/ChatScreen.tsx** — статус под своими сообщениями, "был в
   сети", клик по шапке.
9. **src/components/ProfileDetailSheet.tsx** (новый).
