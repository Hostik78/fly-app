# Бэкенд Fly: состояние и ближайшая работа

## Устройство

- Supabase Auth: вход и аккаунты.
- PostgreSQL в Supabase: анкеты, заметки, лайки, сообщения, блокировки,
  скрытые анкеты, подписки на уведомления. Доступ ограничивается правилами
  в самой базе (RLS), а не только кнопками приложения.
- Supabase Storage: фотографии.
- Supabase Realtime: обновления и индикаторы присутствия/набора текста.
- Vercel, TypeScript: удаление аккаунта, подсказки текста, временный
  тестовый доступ вне аэропорта.
- Supabase Edge Function: отправка Web Push.

Это существующий бэкенд на управляемых сервисах, не отсутствие бэкенда.
Однако готовность к публичному запуску пока не подтверждена.

## Исправления этого этапа

1. `api/delete-account.ts`: ошибка удаления фотографии больше не игнорируется.
   При ошибке аккаунт сохраняется для повтора, успешный ответ не выдаётся.
   Сетевые исключения обрабатываются без внутренних подробностей в ответе.
   Ответы запрещено кешировать.
2. `api/suggest.ts`: сервер проверяет форму тела, допустимые категории, погоду,
   время суток и диапазон температуры до обращения к платному сервису.
   Это НЕ ограничение частоты запросов — оно ещё необходимо отдельно.
3. Добавлены тесты настоящих обработчиков с заменой внешних сервисов.
   Проверки не удаляют реальные аккаунты и не вызывают платный ИИ.
4. Совместимое обновление зависимостей снизило отчёт npm audit с 17 до 5
   предупреждений (3 high, 2 moderate). Остаток связан с инструментами
   @vercel/node: ajv, path-to-regexp, undici и зависимыми пакетами.
   Принудительное несовместимое обновление не применялось.

Независимый обзор двух обработчиков и их тестов не обнаружил новых ошибок.
Это не заменяет проверку внешних сервисов: они в тестах подменены.

## Приоритеты до запуска

1. Восстановить служебный доступ к Supabase для проверки действующих политик:
   `supabase migration list` сейчас возвращает Unauthorized (401).
   Это ошибка административного доступа, не доказательство отказа приложения.
2. Проверить и закрыть чтение живых данных через список заблокированных,
   публичные фотографии, общие каналы присутствия и индикаторы набора текста.
   Проблемные пути выявлены в исходниках; актуальная конфигурация production
   и проверки обхода несколькими тестовыми аккаунтами ещё нужны.
3. Проверить получателей уведомлений после блокировки и допустимые адреса
   push-подписок, чтобы сервер не отправлял запросы на произвольные адреса.
4. Ввести серверные ограничения частоты и размера сообщений/заметок/подсказок.
5. Проверить полное удаление данных, файлов и доступ со старой сессией.
   Текущее исправление очищает штатный путь avatar.jpg; оно не реализует
   новую систему очистки произвольных загруженных файлов и отзыва сессий.
6. Проверить зависимости, защитные заголовки и исключения при публикации.
7. Пройти вход → анкета → заметка → взаимный лайк → переписка → блокировка
   на нескольких изолированных аккаунтах, затем на настоящих телефонах.

Географическое ограничение сейчас нельзя считать доказанной серверной защитой.
Не публиковать тестовые анкеты в общую ленту ради проверки.
Анимация волны отложена: сейчас приоритет — безопасность и надёжность.
