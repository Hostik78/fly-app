# Переход на приватные фотографии

Эта процедура нужна потому, что старый бакет `avatars` был публичным. Уже
выданную публичную ссылку нельзя сделать приватной одной настройкой: старый
файл, CDN-кеш или скачанная копия могут продолжить жить отдельно.

## Порядок выпуска

1. Применить миграцию `20260927102120_prepare_private_photos.sql`.
   Она только создаёт закрытый бакет, таблицы и проверяемые функции. Старый
   бакет не закрывается.
2. Проверить, что production-код новой версии собран, а в текущем клиенте нет
   вызовов `getPublicUrl('avatars', ...)` и прямых ссылок на `avatars`.
3. В согласованное окно остановить старые загрузки, выполнив
   `supabase/operations/freeze-legacy-photos.sql`. Старый бакет становится
   закрытым, а новые записи в него запрещаются. Это не удаляет файлы.
4. Запустить `node scripts/migrate-private-photos.mjs --check`, затем
   `--copy`. Скрипт копирует файлы через Storage API, сверяет содержимое по
   SHA-256 и записывает соответствие в закрытую таблицу. При ошибке старый
   файл остаётся.
5. Для каждого файла проверить доступ нового API владельцем, разрешённым
   собеседником, посторонним пользователем и заблокированной парой.
6. Убедиться, что старый бакет пуст, публичные и старые подписанные ссылки
   больше не отдают файлы. CDN-проверку нужно выполнить отдельно: SQL не видит
   уже закешированные ответы.
7. Запустить `node scripts/migrate-private-photos.mjs --retire`, затем
   `supabase/operations/activate-private-photos.sql`. Последняя команда
   включает выдачу только после проверки пустого старого бакета и закрытого
   нового бакета.
8. После активации проверить отзыв доступа, блокировку в обе стороны, выход,
   замену фотографии и удаление аккаунта. Разблокировка не возвращает старое
   разрешение автоматически.

## Нельзя делать

- Нельзя публиковать новую клиентскую версию между шагами 1 и 7: rollout-флаг
  специально вернёт отказ вместо возврата к публичному фото.
- Нельзя удалять `storage.objects` SQL-запросом. Для файлов используется только
  Storage API.
- Нельзя считать удаление старого файла доказательством удаления уже скачанной
  копии. Такой отзыв физически невозможен.
- Нельзя запускать процедуру на production без резервной копии и журналов
  результата по количеству файлов; при отсутствии доступа к Supabase запуск
  останавливается до восстановления управляющего доступа.
